### 2.2 macOS: EndpointSecurity Framework

**技术特点：**
- 用户态 System Extension，无需开发内核扩展
- 原生支持 AUTH（同步阻断）和 NOTIFY（异步通知）事件
- Apple 严格管控，需申请 `com.apple.developer.endpoint-security.client` 权限

**事件覆盖：**
```
ES_EVENT_TYPE_AUTH_EXEC         // 进程执行授权
ES_EVENT_TYPE_AUTH_OPEN         // 文件打开授权
ES_EVENT_TYPE_AUTH_SIGNAL       // 信号发送授权
ES_EVENT_TYPE_AUTH_UNLINK       // 文件删除授权
ES_EVENT_TYPE_NOTIFY_WRITE      // 文件写入通知
ES_EVENT_TYPE_NOTIFY_FORK       // 进程创建通知
... 100+ 事件类型
```

**Rust 绑定可用性：**
- `endpoint-security` crate 提供完整封装
- Santa 项目 C++/Objective-C 实现可作为参考

### 2.3 Windows: ETW + Minifilter

**ETW (Event Tracing for Windows)：**
```
优点：
  • 用户态，开发门槛低
  • 丰富的内置 Provider（进程、网络、注册表等）
  • 无需驱动签名

缺点：
  • 仅监控，无法阻断
  • 可被恶意软件绑定和篡改
  • 部分事件存在延迟
```

**Minifilter Driver：**
```
优点：
  • 内核级，可阻断文件操作
  • 高性能，低延迟
  • 完整的文件系统访问控制

缺点：
  • 需要 EV 代码签名证书（约 $300-500/年）
  • 开发复杂度高
  • 驱动崩溃可能导致蓝屏
```

**推荐方案：双层架构**
```
┌─────────────────────────────────────────┐
│  应用层 (Rust)                          │
│  • 规则引擎 • 策略评估 • 日志收集       │
└──────────────────┬──────────────────────┘
                   │ gRPC/Named Pipe
┌──────────────────┴──────────────────────┐
│  数据采集层                              │
│  ├── ETW Consumer (用户态监控)          │
│  └── Minifilter Driver (文件阻断)       │
└─────────────────────────────────────────┘
```

### 2.4 Linux: eBPF + audit

**eBPF (Extended Berkeley Packet Filter)：**
```
优点：
  • 内核态运行，高性能
  • JIT 编译，接近原生性能
  • 安全沙箱，不会导致内核崩溃
  • LSM (Linux Security Module) 支持阻断（内核 5.7+）
  
缺点：
  • 需要较新内核（推荐 5.10+）
  • 老旧发行版支持有限
  • 学习曲线较陡
```

**audit 子系统：**
```
优点：
  • 所有 Linux 发行版原生支持
  • 配置简单
  • 稳定可靠

缺点：
  • 仅审计，无法阻断
  • 高负载下可能丢失事件
  • 性能开销较大
```

**推荐方案：分层降级**
```
检测运行时环境：
  └─ 内核 >= 5.10 且支持 CO-RE
       ├─ 是 → 使用 eBPF (libbpf-rs)
       └─ 否 → 降级到 fanotify + audit
```

### 4.2 核心 Trait 定义

```rust
// src/platform/mod.rs

use std::path::Path;
use async_trait::async_trait;

/// 平台事件提供者 trait
#[async_trait]
pub trait PlatformEventProvider: Send + Sync {
    /// 订阅指定类型的事件
    async fn subscribe(&self, events: &[EventType]) -> Result<(), PlatformError>;
    
    /// 取消订阅
    async fn unsubscribe(&self, events: &[EventType]) -> Result<(), PlatformError>;
    
    /// 获取下一个事件（阻塞）
    async fn next_event(&self) -> Option<SecurityEvent>;
    
    /// 响应 AUTH 类型事件
    fn respond(&self, event_id: EventId, decision: Decision, cacheable: bool);
    
    /// 设置事件过滤规则（Mute）
    fn set_mute_rules(&self, rules: &[MuteRule]) -> Result<(), PlatformError>;
}

/// 代码签名验证 trait
pub trait CodeSignatureVerifier: Send + Sync {
    fn verify(&self, path: &Path) -> Result<CodeSignature, VerifyError>;
    fn get_signer_info(&self, path: &Path) -> Result<SignerInfo, VerifyError>;
}

/// 进程信息查询 trait
pub trait ProcessInspector: Send + Sync {
    fn get_process_info(&self, pid: u32) -> Result<ProcessInfo, InspectError>;
    fn get_process_tree(&self, pid: u32) -> Result<Vec<ProcessInfo>, InspectError>;
    fn is_process_running(&self, pid: u32) -> bool;
}

/// 文件系统监控 trait
pub trait FileSystemWatcher: Send + Sync {
    fn watch_paths(&self, paths: &[WatchPath]) -> Result<(), WatchError>;
    fn unwatch_paths(&self, paths: &[WatchPath]) -> Result<(), WatchError>;
}
```

### 4.3 平台实现示例

```rust
// src/platform/macos/mod.rs
#[cfg(target_os = "macos")]
pub mod macos {
    use endpoint_security::*;
    use super::*;

    pub struct MacOSEventProvider {
        client: EsClient,
        event_rx: Receiver<SecurityEvent>,
    }

    #[async_trait]
    impl PlatformEventProvider for MacOSEventProvider {
        async fn subscribe(&self, events: &[EventType]) -> Result<(), PlatformError> {
            let es_events: Vec<es_event_type_t> = events
                .iter()
                .map(|e| e.to_es_event_type())
                .collect();
            
            self.client.subscribe(&es_events)
                .map_err(|e| PlatformError::SubscribeFailed(e.to_string()))
        }

        async fn next_event(&self) -> Option<SecurityEvent> {
            self.event_rx.recv().await.ok()
        }

        fn respond(&self, event_id: EventId, decision: Decision, cacheable: bool) {
            let es_result = match decision {

                Decision::Deny => ES_AUTH_RESULT_DENY,
            };
            
            self.client.respond_auth_result(event_id.into(), es_result, cacheable);
        }
    }
}
```

### 4.4 核心业务层设计

```rust
// src/engine/authorizer.rs

pub struct Authorizer<P: PlatformEventProvider> {
    provider: Arc<P>,
    rule_engine: Arc<RuleEngine>,
    decision_cache: Arc<DecisionCache>,
    telemetry: Arc<Telemetry>,
    config: AuthorizerConfig,
}

impl<P: PlatformEventProvider> Authorizer<P> {
    pub async fn run(&self) -> Result<(), EngineError> {
        self.provider.subscribe(&[
            EventType::ProcessExec,
            EventType::ProcessFork,
        ]).await?;

        loop {
            if let Some(event) = self.provider.next_event().await {
                self.handle_event(event).await;
            }
        }
    }

    async fn handle_event(&self, event: SecurityEvent) {
        match event {
            SecurityEvent::ProcessExec(exec_event) => {
                // 1. 检查缓存
                if let Some(cached) = self.decision_cache.get(&exec_event.cache_key()) {
                    self.provider.respond(exec_event.id, cached.decision, true);
                    return;
                }

                // 2. 评估规则
                let context = self.build_context(&exec_event).await;
                let decision = self.rule_engine.evaluate(&context);

                // 3. 响应并缓存
                self.provider.respond(exec_event.id, decision, decision.is_cacheable());
                
                if decision.is_cacheable() {
                    self.decision_cache.insert(exec_event.cache_key(), decision);
                }

                // 4. 记录遥测
                self.telemetry.record_exec_event(&exec_event, &decision);
            }
            _ => {}
        }
    }
}
```

## 九、结论与建议

### 9.1 核心结论

**1. 跨平台统一架构完全可行**
- 通过分层抽象设计，核心业务逻辑可实现 70%+ 的代码复用
- 平台差异被隔离在适配层，对上层业务透明
- 行业已有成功案例（CrowdStrike、HarfangLab、Wazuh）

**2. Rust 是最佳语言选择**
- 性能媲美 C/C++，内存安全有编译器保障
- 跨平台编译成熟，一套代码多端构建
- 安全产品行业趋势，Google/Microsoft/Linux 内核均已采用
- HarfangLab 实践证明：性能提升 3x，资源降低 3x

**3. 分阶段实施策略**
- 小团队应采用 MVP 策略，核心功能优先
- 建议从 macOS 或 Linux 起步（门槛低）
- Windows 阻断能力可后期补充
